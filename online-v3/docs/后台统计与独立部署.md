# 后台统计与独立部署

问卷与后台保持相同的米白纸张底色、深蓝文字、陶红与灰绿图表，以及“心动之间”的标题样式。概览采用主题摘要和回收趋势；后台同时支持全部 41 道题的分布、共同题的分组比较、答卷详情、分页及 CSV / JSON 导出。

逐题分析保留题目下拉选择，并提供“下一题”按钮，按下拉列表的章节与题目顺序切换，显示当前位置。到最后一题时按钮停用；筛选或刷新数据保留当前题目。

## 地址与进程

| 用途 | 域名 | 服务器监听 | 启动文件 |
| --- | --- | --- | --- |
| 公开问卷 | `query.linxiksp.cn` | `127.0.0.1:3100` | `server/index.mjs` |
| 私有后台 | `admin.query.linxiksp.cn` | `127.0.0.1:3101` | `server/admin.mjs` |

后台首页在独立域名的 `/`。问卷域名的 `/admin`、旧后台资源及 `/api/admin/*` 返回 404；后台不提供问卷提交接口。两个服务共用现有 `submissions-v3.json` 和 `admin-auth.json`，不复制、转换或重建生产答卷，不更改已有密码。

后台进程使用：

```ini
NODE_ENV=production
ADMIN_HOST=127.0.0.1
ADMIN_PORT=3101
SURVEY_ADMIN_ORIGIN=https://admin.query.linxiksp.cn
SURVEY_DATA_DIR=/home/codex/xindong-survey-v3/data
SURVEY_SECURE_COOKIE=true
SURVEY_TRUST_PROXY=loopback
```

`SURVEY_ADMIN_ORIGIN` 必须与浏览器地址完全一致且不带尾斜线。监听限制在服务器本机，不需要向公网开放 3101 端口。服务以用户级 systemd 运行，名称为 `xindong-admin.service`；公开问卷仍为 `xindong-survey.service`。

```sh
systemctl --user status xindong-admin.service
systemctl --user restart xindong-admin.service
journalctl --user -u xindong-admin.service -n 50 --no-pager
```

## 证书与反代

服务器面板新建站点 `admin.query.linxiksp.cn`，配置覆盖该完整域名的有效 HTTPS 证书，然后反代到 **`http://127.0.0.1:3101`**。不要加 `/admin` 路径。保留 `Host` 请求头，传递真实来源地址，后台 `/api/` 禁止缓存。可直接参照 [Nginx 配置示例](nginx-admin.conf.example)，替换证书路径。

Cloudflare 中添加该域名的 DNS 记录，并为 `admin.query.linxiksp.cn/api/*` 设置缓存绕过；不能让“缓存所有内容”规则覆盖管理 API。边缘证书和源站证书均需覆盖完整域名，使用 HTTPS 访问。现有管理密码沿用，不需要再次初始化。

配置后应检查：

- 后台首页展示“心动之间 · 问卷统计”，没有证书错误；
- `/api/admin/session` 未登录时返回 `authenticated: false`；
- `/api/admin/summary` 未登录时返回 401；
- 管理 API 响应包含 `Cache-Control: private, no-store…`，Cloudflare 未返回缓存命中；
- 登录后读取现有答卷，退出后不能继续读取统计；
- 公开问卷仍能填写，公开地址不再承载后台入口。

## 统计口径

概览按“婚恋意愿、现实考虑、支持需求”组织三组摘要。主要选择按原始计数取最大值，并列项全部保留，“尚未确定”“没有需求”可以成为主要选择；没有有效回答时不生成结论。各项保留自己的有效人数和适用范围，点击可查看原题。摘要不合成跨题分数，也不据此推断因果。

“日常开支压力较大或很大”合计 F01 的 `large` 与 `very_large`；“选择至少一项支持需求”按 H01 有效人数减去选择排他项 `none` 的人数计算，避免把一个人的多个需求重复计数。F02 的经济、居住与工作安排，以及 F03 感知到的家庭结婚期待分别按原选项展示，沿用明确目前非已婚者的范围。

回收趋势可切换截至末日最近 7、14、30 天，日期筛选较窄时截取实际范围。每日新增补齐零回收日期；累计回收包含当前筛选范围内、展示窗口之前已收到的答卷，切换时段不会重新从零累计。概览显示本段新增、截至末日累计和日最高回收，提供每日明细；点击日期可查看同一筛选范围的当日记录。趋势展示调查回收过程。

默认只展示明确高校在读的样本，可切换至全部提交或在读资格未透露者。日期、学习阶段、性别及关系路径筛选同时作用于概览、逐题分析、分组表、记录列表和导出；导出使用已成功应用的筛选条件。日期按北京时间、包含起止日计算。

每题百分比分母为该题、该情景的有效选择人数。“尚未确定”“没有相关经历”“无需求”等仍是有意义的选择，保留各自类别；不愿回答、不适用、难以代入、主动跳过、未答及按路径未展示分别保留状态，不计入选择分母。多选题按选择某项的人数计算，比例之和可以超过 100%。没有有效选择时显示“—”，不会生成示例比例。

未来结婚意愿 U01、时间安排 U02、考虑因素 F02、家庭结婚期待 F03 仅统计 D04 明确目前非已婚者。D04 未透露的相关答卷显示另列人数，避免将其直接推定为未婚。已婚路径未展示的题目计入“按分支未展示”。F03 家庭期待方向与 M07 家庭影响强度分开统计。

情景题按实际版本分别展示题干与分布，不能合并求平均：

- R03：收取方的个人期望、支付方的预计预算、通用情景的安排偏好；
- R02：本人希望生育但伴侣不希望、本人不希望但伴侣希望、未明确方向，以及不同角色表述；
- V01 / V02：男方、女方与通用伴侣表述。

分组比较只用于没有不同题干版本的选择题，始终显示每组本题有效人数。R01 包含已有子女者对再生育的想法。用时中位数仅采用页面记录的正整数秒数；没有记录或零秒不当作实际填写时间。开放回答只显示数量，原文保留在授权后的单份详情及导出中，不生成词云、情感判断或综合分数。样本分布用于描述，不作为因果结论。

## 数据与更新

提交仅由公开问卷进程写入，通过临时文件原子替换；后台读取同一数据文件。更新程序无需移动数据。生产答卷、密码校验文件、服务环境配置和备份均留在服务器私有目录。源码与运行包不携带答卷、管理密码或采访预设回答。

管理会话使用 HttpOnly、SameSite=Strict Cookie，生产环境增加 Secure；状态修改验证来源与 CSRF Token。服务重启会使当前会话失效，重新登录即可。查询与导出接口始终禁止缓存。

`npm run check:admin` 检查统计分母、缺失状态、角色情景、日期边界、样本筛选、主题并列、支持需求去重、累计承接、分组与空数据，以及鉴权、来源校验、CSRF、导出和公开提交。`npm run check:admin:browser` 在独立临时目录验证登录、主题跳转、回收时段、日期明细、筛选、详情、导出、空数据、网络失败、键盘导航及 320 / 390 / 768 / 1440 像素布局，不连接生产数据。
